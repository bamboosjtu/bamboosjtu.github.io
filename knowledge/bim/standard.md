# BIM 标准体系

BIM 标准体系的核心并不是规定“模型应该画多细”，而是建立一套跨组织、跨专业、跨软件、跨阶段的信息协同规则。

它要解决的根本问题是：

> **工程信息为什么需要、需要什么、由谁产生、如何表达、如何交换、如何验证、如何审核批准，以及如何在项目和资产生命周期中持续使用。**
> **工程信息从需求产生，到生产、交换、验证、协同和正式发布的全过程。**

| 层次          | 核心问题                     | 主要相关标准 / 概念   |
| ------------- | ---------------------------- | --------------------- |
| 1. 用途       | 为什么需要这些信息？         | OIR / AIR / PIR / IDM |
| 2. 要求       | 需要什么信息、什么时候需要？ | EIR / LOIN            |
| 3. 责任       | 谁生产、谁提交？             | BEP / TIDP / MIDP     |
| 4. 语义       | 对象、分类、属性是什么意思？ | bSDD / IFC            |
| 5. 交换       | 信息用什么开放结构表达？     | IFC                   |
| 6. 验证       | 如何证明信息满足要求？       | IDS                   |
| 7. 协同与管理 | 如何审核、发布、协同和闭环？ | ISO 19650 / CDE / BCF |

不同标准分别负责其中不同环节。从整体上看，可以把 BIM 标准体系分成两条互补的主线：

```text
ISO 19650
信息管理与治理
        │
        ├── OIR / AIR / PIR / EIR
        ├── BEP / TIDP / MIDP
        ├── CDE
        └── PIM / AIM

ISO 7817
Level of Information Need
        │
        ├── Geometrical information
        ├── Alphanumerical information
        └── Documentation

ISO 29481
IDM
业务过程与交换需求

buildingSMART / openBIM
        ├── bSDD：语义服务
        ├── IDS：机器可读信息要求
        ├── IFC / ISO 16739：工程信息数据模式
        └── BCF：问题协同
```

可以粗略理解为：

> **ISO 19650 主要回答“工程信息应该怎样被管理”。**  
> **openBIM 主要回答“工程信息怎样被开放定义、交换、验证和协同”。**

---

## 一、ISO 19650

ISO 19650 是整个 BIM 信息管理体系中最重要的主线之一。它关注的重点不是三维建模技术，而是：

> **在工程全生命周期中，如何组织、生产、交换、审核、批准和管理信息。**

因此，ISO 19650 更接近一种“信息管理框架”。它解决的问题包括：

- 为什么需要某些信息；
- 谁负责提供信息；
- 在什么阶段提供；
- 信息如何进入受控流程；
- 哪些信息可以共享；
- 哪些信息可以正式发布；
- 如何管理版本、状态、权限和责任。

### 1. 信息需求体系

ISO 19650 中一个重要思想是：

> **信息生产之前，首先必须明确为什么需要这些信息。**

因此，信息需求会逐层分解。

可以简化理解为：

```text
OIR
 ↓
AIR / PIR
 ↓
EIR
 ↓
BEP
 ↓
TIDP / MIDP
```

这不是简单的文件清单，而是一条“需求—响应—交付”的逻辑链。

#### OIR

OIR（Organizational Information Requirements），即**组织信息需求**。它回答：

> **组织为了经营、治理和决策，需要什么信息？**

OIR 位于最高层。它不是针对某一个具体项目，而是从组织管理目标出发，定义信息需求的来源。

```text
组织目标
   ↓
为什么需要信息
```

#### AIR

AIR（Asset Information Requirements），即**资产信息需求**。它回答：

> **资产进入运营阶段后，需要保留和维护哪些信息？**

AIR 面向资产生命周期。它把组织层面的需求进一步转换为资产管理需要的信息要求。

```text
OIR
 ↓
资产管理需要
 ↓
AIR
```

#### PIR

PIR（Project Information Requirements），即**项目信息需求**。它回答：

> **为了管理某一个具体项目，需要什么信息？**

PIR 面向项目建设过程。

```text
OIR
 ↓
项目管理需要
 ↓
PIR
```

AIR 和 PIR 的区别在于关注对象不同：

| 类型 | 主要关注 |
|---|---|
| AIR | 资产运行和长期管理 |
| PIR | 项目实施和项目管理 |

#### EIR

EIR（Exchange Information Requirements），即**交换信息要求**。它回答：

> **在某一个信息交换节点，接收方要求提供什么信息？**

这是信息需求开始进入实际交付的重要环节。EIR 需要明确：

- 交换什么信息；
- 在什么节点交换；
- 信息需要达到什么要求；
- 以什么方式进行交付。

```text
OIR / AIR / PIR
        ↓
具体交换需求
        ↓
       EIR
```

---

### 2. BEP、TIDP、MIDP

如果说 EIR 代表“要求”，那么 BEP、TIDP 和 MIDP 主要代表项目团队如何响应这些要求。

#### BEP

BEP（BIM Execution Plan），即**BIM 执行计划**。它回答：

> **项目团队准备怎样满足既定的信息要求？**

可以简单理解为：

```text
EIR = 要什么
BEP = 准备怎么做
```

BEP 的重点是执行方法和组织方，是需求和实际信息生产之间的重要桥梁。

#### TIDP

TIDP（Task Information Delivery Plan），即**任务信息交付计划**。它回答：

> **某个任务团队什么时候交付什么信息？**

它把总体要求进一步落实到具体任务团队。核心问题是：

```text
谁
在什么时候
交什么
```

---

#### MIDP

MIDP（Master Information Delivery Plan），即**总体信息交付计划**。它用于协调项目整体的信息交付。

> **多个 TIDP 经过协调后形成项目级总体交付计划。**

```text
多个 TIDP
    ↓
协调与汇总
    ↓
MIDP
```

---

### 3. CDE

CDE（Common Data Environment），即**共用数据环境**，是 ISO 19650 信息管理思想落地的重要机制。CDE 真正管理的是信息的受控流转，而不是“所有人都可以上传和下载文件的共享盘”。通常关注：

- 信息身份；
- 状态；
- 版本；
- 权限；
- 审核；
- 授权；
- 发布；
- 审计轨迹。

典型状态可以简化理解为：

```text
WIP
 ↓
Shared
 ↓
Published
 ↓
Archived
```

其核心思想是：**信息是否可以被正式使用，不由文件是不是“最新”决定，而由其治理状态决定。**

例如：

```text
V3  Published
V4  Shared
```

即使 V4 的时间更新，它也不一定能够替代已经正式发布的 V3。

---

### 4. Information Container

ISO 19650 使用 Information Container 的思想理解被管理的信息。Information Container 可以是：

- 模型；
- 图纸；
- 文档；
- 表格；
- 数据集；
- 图片；
- 报告；
- 其他信息载体。

也就是**BIM 信息管理并不等于三维模型文件管理。**ISO 19650 管理的是“信息”，而不是某一种特定文件格式。

---

### 5. PIM 与 AIM

ISO 19650 区分项目阶段和资产阶段的信息模型。

#### PIM

PIM（Project Information Model），即**项目信息模型**。

主要服务项目建设过程中的信息管理。

#### AIM

AIM（Asset Information Model），即**资产信息模型**。主要服务资产运营阶段的信息管理。**不是简单保存项目阶段产生的全部信息。**

```text
             Delivery Phase
AIM ───────────→ PIM
既有相关信息       │
                 │
                 ↓
           经验证的相关信息
                 │
                 ▼
                AIM
          Operational Phase
```

## 二、ISO 7817

### LOIN

过去行业中常使用 LOG、LOI 等术语描述模型深度；ISO 7817-1 则采用统一的 Level of Information Need 框架，从 geometrical information、alphanumerical information 和 documentation 三方面规定信息需求。

**LOG**（Level of Geometry），几何表达需要达到什么程度？

**LOI**（Level of Information），非几何信息需要达到什么程度？

**LOIN**（Level of Information Need）的核心思想是**为了完成某一个明确用途，需要多少信息？**

## 三、openBIM

### 1. IDM

IDM（Information Delivery Manual），即**信息交付手册 / 信息交付方法**。

IDM 从业务过程出发分析信息交换，主要回答：

- 为什么需要这次信息交换？
- 谁向谁提供信息？
- 在什么业务节点发生？
- 需要交换什么信息？

因此，IDM 的核心是：**业务过程与信息交换需求。**

可以理解为：

```text
业务过程
   ↓
识别信息交换节点
   ↓
明确交换需求
```

IDM 不主要负责规定某一个 IFC 文件应该长什么样。它解决的是 IFC、IDS 等技术标准之前的业务问题：**为什么要交换这些信息？**

---

### 2. bSDD

bSDD（buildingSMART Data Dictionary），解决的是“这个词到底是什么意思”。**它关注的是**语义统一**。**

工程领域中常见的问题是：不同组织、不同软件、不同语言可能使用不同名称表达同一个概念。

例如：

```text
名称 A
名称 B
名称 C
   ↓
同一个工程概念
```

如果只靠字段名称，机器很难判断这些字段是否表达同一个含义。

因此 bSDD 的作用可以理解为：**给工程对象、分类、属性等建立机器可理解的共同语义定义。**

一个概念不仅要有名称，还可以定义：

- 含义；
- 数据类型；
- 单位；
- 适用对象；
- 分类关系；
- 多语言表达。

---

### 3. IDS

IDS（Information Delivery Specification），即**信息交付规范**。IDS 解决的是**如何把信息要求表达成机器可以自动检查的规则。**

例如，一个信息要求可能是：

```text
某类对象
必须具有
某个属性
```

人可以阅读自然语言要求，但软件很难稳定地理解自然语言规范。IDS 的作用就是把其中适合自动验证的部分形式化。因此可以把 IDS 理解为：**机器可读的信息要求。**IDS 关注的问题包括：

- 哪些对象适用；
- 必须具备哪些属性；
- 属性值需要满足什么条件；
- 分类或关系是否满足要求。

```text
信息要求
   ↓
IDS
   ↓
机器验证规则
```

---

### 4. IFC

IFC（Industry Foundation Classes） 是 openBIM 体系中最核心的开放标准之一。它不只是“BIM 文件格式”，更准确的定位是：**开放的工程信息模型和数据结构。**IFC 需要描述的不只是几何，还包括：`Object + Type + Property + Relationship + Representation`。

> **IFC 的核心不是“把三维模型导出成 .ifc 文件”，而是以开放结构表达工程对象及其语义。**

#### Object / Occurrence

Occurrence 表示现实世界中的一个具体对象。它回答**是哪一个对象？**

#### Type

Type 表示多个对象可以共享的类型或规格定义。它回答**这一对象属于哪一种类型定义？**

```text
Occurrence = 哪一个
Type       = 哪一种
```

#### Property

Property 表示对象的特征。它回答**这个对象具有什么属性？**需要注意：Type 与 Property 是两个不同维度。一个 Property 可以属于 Type，也可以属于具体的 Occurrence。

#### Classification

Classification 表示**按照某套分类体系，这个对象属于什么类别？**

#### Relationship

**IFC 更接近一个由对象和关系组成的工程信息网络，而不是简单的模型树。**一个对象可以同时具有：

- 空间关系；
- 类型关系；
- 分类关系；
- 系统关系；
- 连接关系；
- 分解关系等。

#### Representation

Representation 回答对象如何被几何或图形表达？一个对象即使没有几何 Representation，仍然可以作为信息对象存在。

#### Placement

Placement 回答对象在几何空间中的位置在哪里？

#### Property Set

Property Set（Pset）用于组织一组具有共同语义的属性。它的意义不只是把若干字段放在一起，而是：**按照语义组织对象属性。**

---

### 5. BCF

BCF（BIM Collaboration Format），它主要用于围绕 BIM 对象进行问题协同。BCF 可以记录：

- 问题描述；
- 对象定位；
- 视图；
- 状态；
- 责任；
- 协作信息。

BCF 的核心价值是：**围绕模型对象交换问题，而不是反复交换完整模型文件。**因此，BCF 更偏向协作层，但需要注意：**BCF 可以承载问题及其状态，但并不负责定义完整的业务审批和整改流程。**

---

### 6. 关系总结

| 标准 / 机制 | 核心问题 |
|---|---|
| IDM | 为什么交换、谁与谁交换、什么时候交换 |
| bSDD | 对象、分类和属性到底是什么意思 |
| IDS | 哪些对象必须具备哪些信息 |
| IFC | 实际工程信息如何开放表达和交换 |
| BCF | 围绕模型对象如何进行问题协同 |

它们不是严格的线性流水线，但可以用下面的关系帮助理解：

```text
                IDM
        业务过程 / 交换需求
                 │
                 ▼
              信息需求
              /      \
             /        \
          bSDD        IDS
         统一语义    机器规则
             \        /
              \      /
                IFC
           实际工程信息
                 │
                 ▼
               BCF
             问题协同
```

其中：

```text
bSDD → 定义“是什么意思”
IDS  → 规定“必须有什么”
IFC  → 承载“实际有什么”
BCF  → 处理“哪里有问题”
IDM  → 解释“为什么在这里交换”
```

## 四、总结

ISO 19650更关注**信息管理和治理。**openBIM更关注**开放语义和互操作。**两套体系可以理解为：

```text
              BIM 信息管理
                    │
        ┌───────────┴───────────┐
        │                       │
   ISO 19650                  openBIM
   管理与治理                开放与互操作
        │                       │
 信息需求与交付             IDM / bSDD / IDS
 CDE / 状态管理               IFC / BCF
```

一个完整的 BIM 信息管理体系，通常既需要治理规则，也需要开放的数据表达和交换标准。

**ISO 19650 建立信息管理秩序，openBIM 建立开放互操作能力；二者共同把 BIM 从“建模工具”提升为“工程信息管理体系”。**
