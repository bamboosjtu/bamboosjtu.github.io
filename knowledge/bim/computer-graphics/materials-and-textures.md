# 材质课为什么又讲贴图：数据、规则与表面细节

“已经有纹理了，为什么还要材质？”“讲材质时，怎么又冒出各种贴图？”这两个问题其实指向同一个边界：**纹理保存数据，材质定义这些数据怎样参与着色。**

先不追求照片级画面。用一颗球、一个立方体和一块平面，就能建立足够清楚的理解。

## 一、先分清形状、数据和规则

- **Geometry** 定义形状，并携带法线、UV 等顶点属性。
- **Texture** 是可以被采样的数据资源，常见形式是二维图像，也可以来自程序生成或渲染结果。
- **Material** 定义着色模型、参数与纹理输入。
- **贴图** 在日常说法中，常指纹理被用作某种表面属性的输入。颜色贴图、法线贴图的区别，主要在于数据的含义和使用方式。

一张灰度图装进 `map`，参与表面颜色；装进 `roughnessMap`，控制不同位置的粗糙度。文件看起来都像图片，计算意义却不同。因此教程讲材质时必须讲贴图：这是在解释材质的输入。

## 二、UV 解决“到纹理哪里取数”

三角形顶点在三维空间里，图片通常在二维空间里。UV 为表面建立纹理坐标，让着色过程知道某个表面位置应到纹理的哪里采样。

UV 不是颜色，也不决定材质类型。相同的 UV 可以用于多张对齐的纹理，例如颜色、粗糙度和法线。跨三角形插值时，还需要考虑透视；否则倾斜表面上的纹理可能变形。

并非所有映射都依赖普通 UV。环境映射通常根据方向查找周围的环境，而不是把图片简单贴到模型表面。

## 三、同一颗球，先只换材质

| 材质 | 主要用途 | 初学者先观察什么 |
|---|---|---|
| `MeshBasicMaterial` | 不计算场景灯光的表面显示 | 关掉灯光，仍可显示颜色或颜色纹理 |
| `MeshLambertMaterial` | 简单的漫反射表面 | 明暗与表面朝向有关，没有镜面高光项 |
| `MeshPhongMaterial` | 漫反射加镜面高光 | `shininess` 控制高光集中程度，`specular` 控制镜面反射颜色 |
| `MeshStandardMaterial` | 基于物理的金属度/粗糙度模型 | 粗糙度改变反射分布，金属度改变反射行为 |
| `MeshNormalMaterial` | 法线可视化 | 用颜色观察表面法线方向，不把它当普通物体颜色 |
| `MeshDepthMaterial` | 深度可视化等用途 | 颜色表达与相机相关的深度，不是表面花纹 |
| `MeshMatcapMaterial` | 从预先制作的材质球图像获取外观 | 光照与反射感已编码在图里，不实时响应场景灯光 |

不要把它们理解成由低到高的升级路线。法线材质和深度材质用于观察特定数据；Basic 可以服务于不需要受光照的显示；Standard 则选择了不同的反射模型。

Matcap 让外观很快成立，但贴图里的“光”不是场景里真实存在的一盏灯。它与环境贴图也不同：前者直接提供一种预制表面观感，后者提供来自不同方向的环境信息，如何使用仍取决于材质。

## 四、各种贴图到底改变哪一层

| 输入 | 表达的内容 | 是否移动顶点 |
|---|---|---|
| `map` | 基础颜色，通常还会与材质颜色相乘 | 否 |
| `roughnessMap` | 不同位置的粗糙度 | 否 |
| `metalnessMap` | 不同位置的金属度 | 否 |
| `normalMap` | 用编码的向量扰动着色法线 | 否 |
| `bumpMap` | 根据高度变化估计着色法线的扰动 | 否 |
| `displacementMap` | 按高度值移动已有顶点 | 是 |
| `aoMap` | 预先记录局部遮蔽程度，影响间接照明的部分贡献 | 否 |
| `alphaMap` | 控制表面透明程度，需要配合透明或裁剪设置 | 否 |
| 环境贴图 | 周围不同方向的光照/环境信息 | 否 |

具体支持哪些输入，由材质类型决定，不能把所有贴图塞给任意一种材质。

### 最容易混淆的边界：凹凸不等于位移

凹凸贴图和法线贴图都主要改变**着色时使用的法线**。光照计算因此产生明暗细节，但表面顶点没有改变；从侧面看，原本平直的轮廓仍然平直。

位移贴图改变的是**顶点位置**。即使它常沿顶点法线方向移动，也不能因此归类为只处理法线的技术。它可以改变轮廓和投影阴影，但需要足够密集的网格：只有四个顶点的平面，无法仅靠一张复杂高度图长出密集山峰。

Three.js 的常规位移由顶点着色过程完成，不会自动把新位置写回 CPU 侧的几何数据，也不会凭空增加顶点。位移后的精细法线常需要匹配的法线贴图等方法补足，不能假设渲染器自动重建全部表面法线。

**检验方法**：给同一平面分别加 normal、bump 和 displacement。先看正面明暗，再降低视角看轮廓，最后观察投影阴影。比较“看起来凹凸”与“几何真正移动”。

## 五、环境贴图为什么有时挂在 Scene，有时挂在 Material

环境描述周围各个方向的信息。对支持环境光照的材质，可以给整个场景设置共同环境，也可以给某个材质指定自己的环境输入。

- `scene.environment` 为支持它的物理材质提供共同的环境照明来源。
- `material.envMap` 指定材质自己的环境映射输入，具体用法与材质类型有关。
- `scene.background` 控制背景显示。看见一张背景图，不代表它已经参与照明。

等距柱状投影是把球面方向展开成二维图的一种方式。HDR 图像可以保存较大的亮度范围；加载器负责读数据，mapping 设置说明如何按方向查图，材质才负责把查到的数据用进反射计算。这三个职责不应混为一谈。

AO 也不是另一盏灯。它常用于近似缝隙与接触处对间接光的遮蔽，不能代替会随灯光和物体移动的投影阴影。

## 六、像素、片元、纹素为什么不能一一对应

- **Pixel（像素）**：输出图像中的离散位置。
- **Fragment（片元）**：光栅化产生、尚待测试和着色等处理的候选结果。
- **Texel（纹素）**：纹理中的离散数据单元。

一块很大的纹理显示在远处，许多纹素可能挤进一个屏幕像素。反过来，近距离看纹理时，一个纹素也可能覆盖很多像素。透视、倾斜角度和距离都会改变这种关系。

### 为什么要过滤，再采样

用一个点代表它周围很大的一片细节，可能会漏掉高频变化，表现为闪烁、摩尔纹或锯齿。抗混叠的核心思路是：先对像素覆盖范围内的信息做合适的过滤，再用有限的样本表示它。

这是信号处理的解释，不意味着 GPU 里所有任务都按一条字面上的“先调用 filter，再调用 sample”顺序执行。纹理采样操作本身通常就包含过滤策略。

### Mipmap 解决的是缩小采样，不只是图片文件太大

Mipmap 为纹理准备一组逐渐缩小的图像层级，相当于预先做一部分过滤。远处一个像素覆盖大量纹素时，可以选取合适层级，减少高频细节造成的混叠。

它不会修复错误 UV，也不能解决所有倾斜观察的问题。斜着看表面时，像素在纹理空间的覆盖范围可能很细长，各向异性过滤就是针对这种情况的重要补充。纹理缩小与三角形轮廓锯齿也不是同一个问题，不能期待 mipmap 一并解决。

## 七、真正使用时，按这个顺序选择

1. **先让形状正确。** 用 Normal 或简单受光照材质检查法线与形体，暂不加载复杂贴图。
2. **再决定需不需要光照。** 不需要时从 Basic 开始；需要一般光照表现时，先用纯色 Standard 配合少量灯光。
3. **只加解决具体问题的纹理。** 颜色有空间变化才加颜色贴图；需要细小凹凸观感时考虑 normal/bump；需要真实轮廓变化才考虑位移与网格密度。
4. **最后考虑环境与更复杂效果。** 每加一项，都先说清它改变了什么，并评估成本。

颜色数据与数值数据还要区别对待：普通 sRGB 颜色图片用于 `map` 时应标明相应色彩空间；normal、roughness、metalness 等数据纹理不能一律当作 sRGB 颜色转换。

学会判断“这次是否需要它”，也是掌握概念的一部分。暂时不用一类贴图，不代表学习缺了一块。
