# 具身智能：从视频到机器人动作

具身智能关注智能系统在物理世界中的感知、控制与执行。"从视频到机器人"是其中一条清晰的工程主线：把人类动作视频转换为机器人可以执行的关节轨迹。稳定的知识不在某个 CUDA 安装命令，而在信息流和约束如何逐层变化。

## 一、技术栈总览

| 层级 | 功能类型 | 作用说明 | 代表组件 | 是否学习型 |
| --- | --- | --- | --- | --- |
| 物理仿真层 | 仿真基础设施 | 模拟动力学、碰撞与物理交互 | SAPIEN | 否 |
| 任务与评测层 | Benchmark 框架 | 定义任务、奖励与评测标准 | ManiSkill3 | 否 |
| 感知层 | 视觉重建 | 从图像恢复人体或状态 | PromptHMR | 是 |
| 表示建模层 | 参数化模型 | 表示人体或物体结构 | SMPL-X | 否 |
| 模仿学习建模层 | 概率轨迹学习 | 从示例学习轨迹分布 | GMM / GMR | 是 |
| 策略学习层 | 控制策略学习 | 学习状态到动作映射 | RL / IL / Diffusion Policy | 是 |
| 轨迹生成层 | 约束满足 | 生成满足速度/加速度/jerk 约束的轨迹 | Ruckig | 否 |
| 控制执行层 | 低层控制 | 电机级控制与反馈调节 | PID / MPC | 否 |

完整链路：

```mermaid
flowchart LR
    A[视频帧] --> B[人体检测与跟踪]
    B --> C[人体姿态 / Mesh 恢复]
    C --> D[人体运动序列 SMPL-X]
    D --> E[运动重定向]
    E --> F[机器人关节轨迹]
    F --> G[仿真验证]
    G --> H[真实机器人执行]
```

## 二、三个代表项目

### 1. PromptHMR —— 可提示的人体网格恢复

[PromptHMR](https://github.com/yufu-wang/PromptHMR)（CVPR 2025，Meshcapade/MPI/UPenn）解决的是感知层问题：从单张图片恢复人体的三维姿态与形状（Human Pose and Shape, HPS）。

它的核心创新是把 HPS 估计重新表述为"可提示 (promptable)"的任务——除了像素，还接受两类辅助提示：

- **空间提示**：人脸框（拥挤场景中人体检测失效时人脸检测仍可靠）、部分或完整的人体检测框、分割掩码；
- **语义提示**：体型的自然语言描述（经 CLIP 编码）、两人近距离交互标签。

架构上由三部分组成：处理高分辨率全图以保留场景上下文的 Vision Transformer、把多模态提示映射为 token 的提示编码器、同时注意力于图像 token 与提示 token 并输出 SMPL-X 参数的解码器。训练时随机遮蔽不同输入类型，使模型在推理时能接受任意提示组合。

两个值得注意的扩展：视频版在解码阶段加入时序 transformer 层，产生时间连贯的平滑运动；再结合 metric SLAM 可以估计世界坐标系下的人体运动。

对视频转机器人管线的意义：遮挡、视角、镜头运动和帧间抖动都会影响姿态恢复质量，而"用提示注入旁路信息"是提升鲁棒性的新范式——VLM 懂图像里的人在做什么，度量回归器懂三维人体，两者的协作有明确的上升空间。

### 2. GMR —— 通用运动重定向

[GMR (General Motion Retargeting)](https://github.com/YanjieZe/GMR) 解决表示转换问题：把人类动作数据（SMPL-X、BVH、FBX、PICO 等多种格式）实时或离线地重定向到不同人形机器人的关节空间。

重定向不是简单的关节角复制，需要同时考虑：

- 骨架拓扑与自由度差异；
- 关节限位、速度和加速度约束；
- 足底接触、平衡与自碰撞；
- 动作语义和末端执行器目标保持。

GMR 把这些约束封装为通用工具，让"人做了什么"到"机器人如何近似完成"这一步标准化。

### 3. video2robot —— 完整管线参考实现

[video2robot](https://github.com/AIM-Intelligence/video2robot) 把上述环节串成端到端系统：视频帧 → 人体检测跟踪 → 姿态/Mesh 恢复 → 运动序列 → 重定向 → 仿真验证 → 真实机器人执行。它验证了整条链路的工程可行性，也暴露了各环节误差如何在级联中放大——上游姿态抖动会传导为下游轨迹噪声，这正是时序一致性（如 PromptHMR 的时序层）重要的原因。

## 三、系统边界

三个问题必须分开：

- **姿态恢复**解决"人做了什么"；
- **运动重定向**解决"机器人如何近似完成"；
- **控制器**解决"机器人如何稳定执行"。

轨迹在真实机器人执行前必须在仿真中检查稳定性、接触和动力学约束——视觉上相似的动作不一定物理可执行。把三个问题混在同一模型中，会让错误难以定位。

环境与依赖版本以各项目当前文档为准；本笔记只记录稳定的信息流与模块边界。
