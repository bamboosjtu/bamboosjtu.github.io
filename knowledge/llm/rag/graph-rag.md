# GraphRAG

GraphRAG将检索的目标从独立的文本片段转变为在知识图谱中寻找相关的实体、关系、路径或子图，在上下文召回、多跳问答准确率、事实一致性与可解释性等关键指标上较传统RAG具有显著优势。

## 一、工作流程

知识图谱是一种结构化语义网络，它用图结构表达知识：

- 节点（Node/Entity）：表示实体，如“公司 A”“人物 B”“疾病 C”。
- 边（Edge/Relation）：表示实体之间的关系，如“收购”“属于”“因果关系”。
- 属性（Attribute）：节点或边的细节信息，如节点的时间、类型等。

### 1. 图谱构建

知识图谱阶段的目标是从原始数据中构建一个高质量的知识图谱：

- 知识抽取：利用 LLM 或 IE 管线从非/半结构化文本中抽取实体、关系与属性，包含指代消解、别名归一（Normalization）与术语标准化。
- 质量控制：对三元组进行置信度评估、人机协同抽检与冲突消解；必要时通过规则与本体约束做一致性校验。
- 图谱融合：进行实体对齐与去重（Entity Resolution），合并跨来源知识并保留来源/时间戳等溯源信息。
- 存储与索引：落地到图数据库（如Neo4j/NebulaGraph/TigerGraph/Neptune等）并建立必要的属性与关系索引，便于后续高效检索与遍历。

### 2. 图谱检索

图谱检索阶段，当用户提出查询时，系统不再是简单地进行向量相似度搜索，而是执行更复杂的图谱检索操作。混合检索策略是主流趋势：

- 实体定位：先用实体链接（Entity Linking）或向量检索在图中锁定核心实体节点。
- 子图探索：从命中节点出发，利用图查询语言（如Cypher）或遍历算法进行邻域扩展、路径发现与约束过滤（例如限定关系类型、跳数、时间区间与置信度阈值）。
- 结构化证据抽取：将路径与关键节点属性序列化为可读证据片段，或生成子图的文本摘要。
- 高级检索：如GraphRAG采用社区检测（如Leiden）生成多层次摘要，实现“全局-局部”联合检索。

### 3. 增强生成

增强生成阶段，将检索到的结构化知识（如相关实体的属性、实体间的关系路径、描述子图的文本摘要等）与原始查询一同注入到 LLM 提示（Prompt）中。实践要点：

- 提示设计：明确要求模型引用“图证据”，并在回答中给出来源与路径（可作为可选的引用附录）。
- 证据融合：将“结构化三元组/路径”与“原文片段”联合提供，兼顾事实性与文本细节。
- 约束回答：对敏感领域（财务/医疗）可采用模板化输出与字段校验，减少幻觉。

## 二、主流框架

- GraphRAG：做一个“知识地图”，再基于地图回答问题
- LightRAG：只在必要时画“局部草图”
- FRAG：给你一套“可拼装工具箱”
- GraphIRAG：像人一样“查一步想一步”

| 维度                 | GraphRAG                           | LightRAG                  | FRAG                         | GraphIRAG                      |
| -------------------- | ---------------------------------- | ------------------------- | ---------------------------- | ------------------------------ |
| 核心目标             | 用知识图谱增强复杂推理与全局问答   | 轻量级图增强 RAG          | 构建可灵活组合的 RAG 框架    | 通过多轮迭代图检索增强推理     |
| 主要结构             | 全局知识图谱 + 社区摘要 + 分层检索 | 局部图结构 + 向量检索融合 | 多模块可插拔式检索框架       | 图结构 + 迭代式检索循环        |
| 是否依赖完整知识图谱 | 是（构建全局图）                   | 否（构建轻量级局部图）    | 不一定（可选图/向量/混合）   | 是（用于多跳推理）             |
| 检索方式             | 图遍历 + 社区摘要 + 全局/局部混合  | 向量检索 + 局部结构增强   | 可组合（BM25 / 向量 / 图等） | 多轮图遍历 + 动态查询更新      |
| 是否支持多跳推理     | 强                                 | 中等                      | 取决于配置                   | 强（核心设计目标）             |
| 是否迭代检索         | 否（一次检索为主）                 | 否                        | 可选                         | 是（核心机制）                 |
| 复杂度               | 高（构图与社区划分成本高）         | 低                        | 中                           | 中高                           |
| 适用场景             | 企业级知识库、长文档分析、复杂推理 | 资源受限场景、快速部署    | 需要灵活适配不同任务场景     | 多跳问答、复杂关系推理         |
| 代表优势             | 全局语义理解能力强                 | 构建成本低、部署简单      | 高扩展性与任务适应性         | 推理链条动态优化               |
| 代表局限             | 构图成本高，工程复杂               | 全局语义能力弱于GraphRAG  | 缺乏统一范式，依赖设计       | 计算开销高，推理链可能累积误差 |
| 总结                 | 偏全局建模                         | 偏工程轻量                | 偏系统架构                   | 偏推理算法                     |
