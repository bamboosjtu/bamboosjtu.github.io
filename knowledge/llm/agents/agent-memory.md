# 智能体的记忆

人靠记忆把一次次孤立的经验连成能力，智能体也一样。这一篇先建立记忆的分类框架，再用一个真实编码智能体（Pi）拆解各类记忆如何落地，最后落到最实用的场景：给智能体写 memory 文件的开发实践。

## 一、认知分类

| 心理学术语                       | AI术语                          | 实现技术                                                                     |
| -------------------------------- | ------------------------------- | ---------------------------------------------------------------------------- |
| 工作记忆（Working Memory）       | WorkingMemory                   | 纯内存存储 + TTL 过期机制（MemoryManager 调度）                              |
| 情景记忆（Episodic Memory）      | EpisodicMemory                  | 时间序列事件存储（SQLiteDocumentStore），可回放、可追溯                      |
| 语义记忆（Semantic Memory）      | SemanticMemory                  | 知识图谱建模（Neo4jGraphStore）+ 语义向量索引（QdrantVectorStore）           |
| 感觉记忆（Sensory Memory）       | PerceptualMemory                | 多模态向量表示（EmbeddingService + QdrantVectorStore），短暂缓存原始感知信息 |
| 长期记忆（Long-term Memory）     | LongTermMemory（组合概念）      | EpisodicMemory + SemanticMemory + PerceptualMemory 的持久化存储              |
| 陈述性记忆（Declarative Memory） | SemanticMemory / EpisodicMemory | 结构化文本 + 图关系 + 向量检索                                               |
| 程序性记忆（Procedural Memory）  | ToolRegistry / Agent策略        | 工具调用模式、策略规则、Agent行为模板（非显式记忆存储）                      |

## 二、设计要点

- **短期/工作记忆**服务于当前任务的即时需求，任务结束后即可丢弃——最简实现就是一个追加式记录列表加轨迹格式化，见[经典范式](knowledge/llm/agents/agent-principles)中 Reflection 的 Memory 类；
- **长期记忆**沉淀有积累价值的信息，依赖持久化存储与检索：向量检索见 [RAG 技术](knowledge/llm/rag/rag-techniques)，知识图谱路线见 [GraphRAG](knowledge/llm/rag/graph-rag)；
- 记忆的写入策略（总结、压缩、遗忘）与读取时机（每步前检索相关记忆）决定了 Agent 的个性化与连贯性；
- 记忆不是越多越好——无关历史会稀释上下文质量，需要与[评估](knowledge/llm/agents/agent-evaluation)配合验证记忆带来的增益。

## 三、案例：Pi 如何管理四类记忆

RPi](https://github.com/badlogic/pi-mono) 是一个极简主义的编码智能体（Mario Zechner 的 pi-mono 项目）。它刻意保持系统提示词最小化，把"记住什么、忘记什么"的控制权交还给使用者与扩展机制——这让它成为观察智能体记忆管理的绝佳标本。用第一节的分类框架逐项对照：

### 1. 工作记忆：上下文窗口 + 自动压缩

Pi 的工作记忆就是模型的上下文窗口。当接近上限时触发**压缩（compaction）**：自动把较旧的消息摘要化，保留任务主线、丢弃过程细节。

值得注意的设计：压缩逻辑完全可定制——可以实现"按主题分段压缩"、"代码感知的摘要"，甚至换一个更便宜的模型来做摘要。工作记忆的管理策略本身就是可编程的。

### 2. 情景记忆：会话持久化

每次会话自动保存到 `~/.pi/agent/sessions/`，并按工作目录组织。这意味着：

- 昨天调试某个项目时的完整对话轨迹可以回放和续接；
- "继续上次的任务"不是靠模型记得，而是靠 harness 把历史会话重新装载进上下文；
- 情景记忆属于用户数据，不属于模型——换模型不丢历史。

### 3. 语义记忆：分层加载的 AGENTS.md

Pi 启动时按固定顺序加载上下文文件：

```text
~/.pi/agent/AGENTS.md        ← 全局层：跨项目的个人偏好与通用约定
     ↓
父目录链上的 AGENTS.md       ← 组织层：monorepo 根的规范
     ↓
当前目录 AGENTS.md           ← 项目层：本仓库的约定、命令、术语
```

所有命中的文件**拼接注入**，而目录中的 `AGENTS.override.md` 会覆盖同级的默认文件。这套机制相当于给智能体配了一本"可以随时翻阅的百科"：稳定的事实与规则写在文件里，每次启动自动进入上下文，不需要向量检索就能保证关键知识在场。

### 4. 程序性记忆：技能与扩展

Pi 不把操作流程硬编码进系统提示词，而是通过 skills（可发现的能力包）、prompt templates 和 extensions 承载"怎么做"的知识。启动头会列出本次加载了哪些 AGENTS.md、skills 与扩展——程序性记忆是显式可见、可插拔的。

### 5. 案例启示

- 四类记忆对应四种完全不同的工程载体：上下文窗口、会话文件、Markdown 文档、技能包——**没有万能的单一大脑存储**；
- 越稳定的记忆越应该"外置为文件"（语义记忆），越易变的越应该留在会话内（工作记忆）；
- 压缩与分层加载都是"控制注意力"的手段：智能体的记忆力问题，本质是上下文预算分配问题。

## 四、开发实践：写好 memory.md

AGENTS.md / CLAUDE.md / memory.md 这类上下文文件，是目前性价比最高的智能体记忆投资——不需要任何基础设施，一个 Markdown 文件就能显著改变 agent 行为。以下是实践要点。

### 1. 该写什么

| 内容类型 | 示例 |
| --- | --- |
| 项目约定 | "提交信息使用 conventional commits；组件放 src/components" |
| 常用命令 | "测试：npm test；本地起服务：npm run dev --port 3000" |
| 领域术语 | "e基建 2.0 指公司输变电基建管理系统，不要翻译" |
| 踩坑记录 | "Windows 下路径必须用正斜杠；该 API 有 500ms 限流" |
| 验证方式 | "改动后必须跑 tests/test_tools.py 确认通过" |
| 边界约束 | "不要修改 generated/ 目录；不要升级依赖大版本" |

### 2. 不该写什么

- **易变状态**：当前进度、待办清单——放进文件就过期了，过期记忆比没有记忆更糟；
- **大段文档粘贴**：上下文预算宝贵，给出指向即可，让 agent 按需读取；
- **敏感信息**：密钥、内网地址——上下文文件可能被分享、提交或进入日志；
- **重复的平台常识**：agent 已知的东西写了只会稀释重点。

### 3. 分层组织

参照 Pi 的分层模式组织自己的记忆文件：

```text
全局层 ~/.pi/agent/AGENTS.md      → 个人偏好：语言、代码风格、回复习惯
项目层 <repo>/AGENTS.md           → 本仓库事实：结构、约定、命令、边界
临时层 任务简报（会话内提供）     → 本次目标：随任务出现、随任务结束
```

判断一条信息放哪一层的标准：**换个项目还成立吗？** 成立→全局层；只在这个仓库成立→项目层；只在这次任务成立→会话内说，不要落盘。

### 4. 迭代习惯

memory 文件是活的文档，最有价值的写法来源是**纠错记录**：每当自己第二次纠正 agent 同一个错误时，就把这条纠正沉淀进 memory.md。三个月后它会变成一份高度个性化的"agent 驯化手册"——这正是从"用工具"到"积累资产"的转变。
